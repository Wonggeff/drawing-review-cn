# 01 审查流程与交付物

## 一、流程总览

```
① 图纸台账
② 取证能力建设（PDF 文字层检测 / DWG 文字提取 / 图纸渲染）
③ 基础图通读（总说明 / 总平面 / 设计依据 / 防火 / 防水 / 各专业说明）
④ 专业分册并行审查（子代理分批派发）
⑤ 项目级与跨专业核查（主代理亲做）
⑥ 合并、去重、分级
⑦ 交付物生成
```

---

## ① 图纸台账

**目的**：在开始读图前先掌握图纸集全貌，并暴露一批不需要读图就能发现的问题。

命令：
```
python scripts/ledger.py
```

台账本身即可产出以下问题类型：
- 各专业分册张数统计（是否覆盖全部单体？某专业是否异常少？）
- 同名文件重复（同一套图纸重复归档）
- 同一文件夹内图号重复/缺号
- 各单体出图张数异常（某单体明显少于同类）

**必查**：
- 是否存在嵌套同名目录（整目录重复收录）
- 是否存在"某专业只覆盖部分单体"（如给排水只做 12 个单体而项目有 26 个单体）

## ② 取证能力建设

### 步骤 1：检测 PDF 文字层
```
python scripts/extract_pdf.py
```
输出 `_index.json`（每张图的页数、可提取字符数）。**字符数 < 50 的图纸即为无文字层**，
后续只能靠图像识读。字符数正常但内容为乱码的，说明字体缺 ToUnicode 映射，同样不可用。

### 步骤 2：DWG 全量文字提取（中国施工图的关键取证手段）
```
# 需已安装 AutoCAD（含 accoreconsole.exe）
pwsh -File scripts/batch_dump2.ps1
```
输出 `_dwgtext/*.txt`（GBK 编码，含 `TEXT|图层|坐标|文字`）与 `_manifest.csv` 路径映射。
这一步让"跨 200 多个 DWG 检索某个关键词"成为可能，效率远超逐张读图。

### 步骤 3：图纸渲染
```
python scripts/render_all.py      # 渲染全部唯一 PDF 为 PNG（zoom 2.0）
python scripts/findpng.py "路径片段"   # 定位某张图的 PNG
python scripts/crop.py "路径片段" x0 y0 x1 y1 out.png 6   # 局部放大 6 倍
```
图片单边超过约 8192px 会读取失败，需先 crop 分块。

## ③ 基础图通读（不可跳过）

**必读清单**：
1. 施工图设计总说明（一）（二）（三）—— 工程概况表、子项概况表、设计依据、材料做法、标高说明
2. 总平面图 —— 综合技术经济指标一览表、建（构）筑物一览表、设计说明
3. 现状总平面图与总平面图的差异
4. 建筑防火设计说明 —— 防火分区、安全疏散、防火构造、设备用房、装修材料
5. 消防设计专篇（独立文件）
6. 防水设计专项说明
7. 结构设计总说明 —— 工程概况表（±0.000、安全等级、抗震设防类别、地基基础设计等级、
   抗震等级、地下防水抗渗等级、设计工作年限）、材料、桩基、抗浮
8. 给排水 / 电气 / 暖通 / 智能化 设计说明
9. 景观园建说明、植物设计说明、景观给排水说明
10. 室内装修设计说明（DI-01～05）

**重点交叉核对表**（在 ③ 阶段就要做）：
- 子项概况表：**逐行验证"建筑面积 = 计容面积 + 不计容面积"**，并求各单体之和是否等于总建筑面积
- 总平面图建（构）筑物一览表 vs 子项概况表：**层数、建筑高度、使用性质、面积、±0.000**
- 设计说明正文的"单体数量/清单" vs 子项概况表 vs 总平面图一览表
- 各单体建筑图的 ±0.000 绝对标高（用 `gw.py "±0.000("` 或 `gw.py "绝对标高"` 全项目检索）
- 防火分区编号与面积（建筑说明 / 建筑单图图名 / 电气专业三处）
- 设计范围声明中"不在本次范围内"的专业，与送审图纸集实际包含的分册对比

## ④ 专业分册并行审查

### 派发策略
- 按"专业 × 单体簇"切分，单个子代理控制在 **20～80 张图**，超过则再切分
- 并发上限通常为 8，**分批派发**；每批派发后观察完成情况再派下一批
- 主代理自己承担：基础图通读（③）、跨专业核查（⑤）、合并与出件（⑥⑦）

### 子代理提示词必须包含
1. **项目背景**：项目名、地点、单体清单与编号、结构形式、抗震设防、±0.000、
   建设单位/设计单位/审图机构与盖章日期
2. **审查范围**：明确的文件夹/图号前缀 + 预估张数
3. **取图方法**：给出 `findpng.py` / `crop.py` / `gw.py` 的**绝对路径**与用法示例
4. **专业审查要点**：从 references/02 取对应章节直接粘贴
5. **已知线索**（可选但极有价值）：主代理在 ③ 阶段发现的项目级矛盾，
   要求子代理"核实后准确表述，不要照抄"
6. **输出格式**：9 列表格 + 编号前缀 + 写入指定 md 文件 + 返回统计与最严重 8～10 条摘要
7. **禁止编造**：证据不足写"需设计确认"；看不清的不写

### 质量校验
子代理返回后抽查其条目：图号是否真实存在、结论是否与主代理 ③ 阶段的核对结果冲突。
**冲突时以主代理在盖章 PDF 上的复核为准**（子代理可能误读低分辨率图像）。

---

## ⑤ 项目级与跨专业核查（主代理亲做）

清单见 **references/03**。原则：
- 先用 DWG 全量文字做全项目检索（`gw.py`），把散落在各专业的同一参数拉到一起对比
- 再对关键数值用 `crop.py` 在盖章 PDF 上放大确认
- **凡涉及"某数值是否已填写"的判断，必须核对盖章 PDF，不能只看 CAD**
  （CAD 常为未填写的模板或更早版本）

## ⑥ 合并、去重、分级

```
python scripts/merge_findings.py   # → _findings/_merged.md 与 _merged.csv（统一编号 + 统计）
python scripts/make03.py           # → 03_各专业问题明细清单.md
```
合并脚本会自动识别 `编号-序号` / `A01-01` / `S-01` 等编号格式，并以"类别列必须是 A/B/C/D"
过滤非问题表格。新增分册报告后重跑即可。

## ⑦ 交付物生成

```
python scripts/make_docs.py        # → 04_图纸会审记录表.xlsx / .docx
```

**四件套**：
| 文件 | 用途 |
|---|---|
| 01 知识体系与审查要点 | 方法论与依据，会审前培训/备查 |
| 02 问题清单（主件） | 审查结论、三级优先级、一级问题、跨专业矛盾、图纸集完整性、需确认事项 |
| 03 各专业问题明细 | 统一编号的完整明细，逐条可追溯 |
| 04 会审记录表（Word/Excel） | 上会签认用：含设计回复/处理结果/闭环状态空列与四方签认栏 |

---

## ⑧ 会审会议组织建议

1. **按"问题包"分议题**，而不是按专业顺序念清单。典型分组：
   - 基础方案包（基础形式版本冲突、桩基/筏板）
   - 抗浮专项包（抗浮水位、验算、措施）
   - 消防系统包（消防水源、自动灭火、防火分区、疏散）
   - 标高体系包（±0.000 一览表、面层—结构对照、各单体标高矛盾）
   - 木结构设计界面包（上部结构图提供方、防火、柱脚连接）
   - 二次设计界面包（装修、亮化、幕墙、电梯、演艺、标识）
2. **先解决"前置条件"**：签章有效性、变更是否已审图、设计范围与界面。
3. **现场暂停项要写清楚**：哪些部位在取得设计书面确认前不得施工。
4. **答复栏措辞**：会审只做释疑；凡改变原设计已明确内容的一律另行出具《设计变更通知单》，
   避免以会审纪要代替变更，造成结算争议。
5. **签认人资格**：设计单位为项目专业设计负责人（分专业签认）、监理为总监理工程师、
   建设/施工为项目技术负责人。
